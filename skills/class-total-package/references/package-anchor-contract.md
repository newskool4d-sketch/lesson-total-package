# Package Anchor Contract

모듈 간 일관성을 보장하는 공통 앵커 블록 표준. 패키지에 2개 이상 모듈이 선택되면 이 계약을 적용한다.

## Core rule

1. 모듈 산출물을 생성하기 **전에** 앵커 블록을 먼저 확정해 사용자에게 출력한다.
2. 확정된 앵커 블록을 **모든 모듈 산출물 상단에 동일하게 삽입**한다. (요약·변형 금지 — 그대로 복사)
3. 앵커 블록의 어떤 필드도 모듈별로 다르게 표기하지 않는다. 수정이 필요하면 앵커 블록을 먼저 갱신하고 이미 생성된 산출물에도 반영한다.

## Anchor block format

```markdown
> **[수업 패키지 앵커]**
> - 수업 주제:
> - 학교급·학년군: (예: 중학교 1~3학년군 / 고등학교)
> - 교과·단원:
> - 성취기준: (2022 개정 교육과정 코드 + 문장, 예: [9사(일사)01-01] …)
> - 수업 목표: (1~2문장)
> - 핵심 질문: (1개)
> - 핵심 개념: (5개 이하)
> - 학생 활동 동사: (예: 탐색한다, 비교한다, 제안한다)
> - 최종 결과물:
> - 평가 포인트: (활동과 직결된 것만)
```

## Field rules

- **성취기준**: 코드가 불확실하면 추정 표기하지 말고 `(성취기준 코드 확인 필요)`로 남긴다. 확인된 코드만 대괄호 표기.
- **핵심 질문**: 반드시 1개. 모듈별 보조 질문은 핵심 질문 하위로만 배치한다.
- **학생 활동 동사**: 판서·마인드맵·학습지·PBL·수행평가에서 같은 동사를 재사용한다. 새 동사가 필요하면 앵커 블록에 먼저 추가한다.
- **평가 포인트**: 수행평가 모듈이 없더라도 기재한다 (수업형 교사 메모의 관찰 포인트로 사용).

## Verification

패키지 완성 전 확인:

- [ ] 모든 산출물 상단의 앵커 블록이 문자 단위로 동일하다
- [ ] 산출물 본문에 앵커 블록과 모순되는 목표·질문·용어가 없다
- [ ] 성취기준 필드가 코드 확정 또는 `확인 필요` 중 하나로 명시돼 있다
